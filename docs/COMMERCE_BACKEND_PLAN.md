# نقشهٔ بک‌اند، دیتابیس و فروش — ایوان خشتی

## معماری هدف

`Website + Mobile App → HTTPS API → Auth / Content / Commerce services → Database + Object Storage`

ظاهر سایت و اپ هیچ‌وقت مستقیماً به دیتابیس یا کلید مدیریتی متصل نمی‌شوند. API مشترک اجازه می‌دهد دیتابیس یا ارائه‌دهندهٔ هاست بدون بازطراحی رابط عوض شود.

## پیشنهاد شروع

- دیتابیس رابطه‌ای: PostgreSQL؛ Supabase یک گزینهٔ اجرایی سریع است، نه وابستگی اجباری.
- رسانه: Object Storage با URL امضاشده، نسخهٔ اصلی خصوصی و خروجی WebP/AVIF/poster.
- احراز هویت: مدیر با MFA، نقش‌ها و نشست امن HttpOnly؛ پنل عمومی ثبت‌نام مدیر ندارد.
- بک‌آپ: نسخهٔ روزانه دیتابیس، نگهداری خارج از سرور اصلی، آزمون بازیابی دوره‌ای و نسخه‌بندی رسانه.
- انتقال‌پذیری: خروجی JSON/CSV محتوا و نسخهٔ سورس در مخزن خصوصی.

## فروش امن

1. محصول و قیمت در دیتابیس ثبت می‌شود.
2. سایت فقط شناسهٔ محصول را به سرور می‌فرستد.
3. سرور Checkout Session را نزد درگاه می‌سازد.
4. مشتری روی صفحهٔ امن ارائه‌دهنده پرداخت می‌کند.
5. وب‌هوک امضاشده پرداخت را تأیید و سفارش را فعال می‌کند.
6. دسترسی دوره، رسید و ایمیل فقط پس از تأیید سروری صادر می‌شود.

انتخاب درگاه خارجی مانند Stripe یا PayPal و درگاه ایرانی مانند Zarinpal یا IDPay قبل از مشخص‌شدن کشور قانونی صاحب کسب‌وکار، کشور حساب بانکی، ارز و شرایط احراز هویت انجام نمی‌شود. هر ارائه‌دهنده پشت یک Payment Adapter مستقل قرار می‌گیرد تا قطعی یا تغییر یک درگاه، سایت و سفارش‌های دیگر را از کار نیندازد. شماره کارت یا CVV در دیتابیس سایت ذخیره نخواهد شد.

هر درخواست ایجاد پرداخت باید `Idempotency-Key` یکتا داشته باشد. رویدادهای وب‌هوک ابتدا با امضای رسمی ارائه‌دهنده اعتبارسنجی و در دفتر تراکنش ثبت می‌شوند؛ سپس وضعیت سفارش تغییر می‌کند. صفحهٔ بازگشت مرورگر به‌تنهایی اجازهٔ تأیید پرداخت را ندارد. برای خطاهای موقت، صف تلاش مجدد، dead-letter queue، هشدار و تطبیق روزانهٔ سفارش/تراکنش در نظر گرفته می‌شود.

## اعتماد و حقوق

- دامنهٔ رسمی، SSL و ایمیل همان دامنه
- Privacy Policy، Terms، Refund/Cancellation و Cookie notice متناسب با کشور و ابزارهای رهگیری
- نام حقوقی، نشانی تماس و اطلاعات صورتحساب واقعی
- رضایت خبرنامه، امکان لغو عضویت و ثبت نسخهٔ رضایت
- صفحهٔ هر پروژه با تصاویر دارای مجوز و اطلاعات قابل اثبات
- نماد اعتماد فقط وقتی نمایش داده می‌شود که واقعاً صادر شده و برای بازار/درگاه مربوط لازم باشد؛ نماد ساختگی یا نامرتبط ممنوع است.

## مراحل تولید

1. تعیین کشور قانونی، حساب بانکی، ارز و مدل فروش
2. انتخاب دامنه و هاست staging/production
3. ساخت دیتابیس، API، احراز هویت، رسانه و audit log
4. اتصال پنل فارسی، فرم‌ها و خبرنامه
5. اتصال درگاه در sandbox و آزمون وب‌هوک/بازپرداخت
6. صفحات حقوقی و ایمیل تراکنشی
7. تست امنیت، دسترس‌پذیری، سرعت، بک‌آپ و بازیابی
8. تأیید مالک و انتشار دامنه
